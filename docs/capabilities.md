# 外部服务能力中心

后台「系统设置」顶部是一组**能力卡片**：网络代理、人机验证、邮件与模板、Telegram 通知、
AI 模型设置、IP 与地理位置。它们有一个共同口径：

> **面板只提供能力，凭据全部由你自己填。**

项目不内置任何 API Key、站点密钥、SMTP 密码、代理地址或 Bot Token，也不锁定任何一家服务商：
你想用哪家、用几把钥匙、换不换，都由你在后台填。每个能力都带一个「测试」按钮，会**真实**发起
一次请求或投递，把失败原因原样报出来——这样才能区分「密钥填错了」和「网络到不了」。

卡片上的两个标记：

| 标记 | 含义 |
| --- | --- |
| **已配置 / 未配置** | 该能力需要的字段是否填齐（与开关无关，关掉但配过仍算已配置） |
| **已启用 / 未启用** | 该能力此刻是否真的在生效 |

密钥类字段读回来只显示 `******`，保存时：

| 你提交的值 | 结果 |
| --- | --- |
| 没动这个字段（保持 `******`） | **不修改**（与经济设置同一约定） |
| 填了一个新值 | 覆盖为新的 |
| **清空这个字段** | **删除已保存的值**（否则密钥只换不撤：代理密码改了、Bot Token 不想用了都删不掉） |

操作审计只记录改过哪些字段名，不记值——免得密钥顺着日志漏出去。

## 网络代理

服务器在墙内、或需要固定出口时用。支持 `http` / `https` / `socks5` / `socks5h`，可带用户名密码。

- **落地方式**：写进进程环境变量（`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`，
  大小写都写一遍）。`httpx`（默认 `trust_env=True`）、`requests`、`rclone` 都认这套变量，
  所以**不需要改任何调用点**：TMDB 刮削、115、网盘挂载探活、AI 调用、地图接口一起走代理。
- **关闭即清除**：关掉开关会把这些环境变量清干净，不会残留一个已经没用的代理把出站请求全带偏。
- **重启后自动恢复**：启动时会重新应用一次配置。
- **别忘了 NO_PROXY**：内网域名、Emby 上游、媒体库所在 NAS 应当写在「不走代理的地址」里，
  否则面板连自己的上游也会绕一圈代理。
- **测试**：默认探测 `https://www.gstatic.com/generate_204`（极小、无缓存），也可以换成你自己的地址。

## 人机验证

为**登录 / 注册**加一道人机验证，可选 Cloudflare Turnstile、Google reCAPTCHA、hCaptcha。

- 站点密钥是公开信息，由 `/api/user/auth/captcha` 下发给前端挂件；私钥只留在后端。
- **没配置 = 直接放行**：不填密钥不会把站点锁在门外，后台只提示「未配置」。
- 两个动作可以分别开关（只保护注册、或两个都保护）。
- 校验失败一律 400，并把提供方返回的 `error-codes` 带上（例如 `invalid-input-response`），
  同时在「登录与安全日志」里落一条 `人机验证失败`——暴力破解会在这里留下痕迹。
- 令牌是一次性的：前端提交失败后会自动取一个新的，用户不会遇到「第二次点击莫名失败」。
- **测试**：用一个必然无效的 token 打一次 `siteverify`。返回 `invalid-input-response` 说明**密钥有效、
  域名可达**；返回 `invalid-input-secret` 才是密钥错了。这是不依赖真实用户的前提下最直接的验证。

## 邮件与模板（SMTP）

站内通知的「邮件」渠道其实早就实现了投递，以前只能靠手写数据库配置才能启用，现在有界面了。

- 端口 **465 走 SSL**，其余端口走 **STARTTLS**（例如 587）。
- 可单独设置**发件人显示名**与**发件地址**（留空则用 SMTP 账号）；非 ASCII 显示名会做 RFC 2047 编码，
  否则部分邮件客户端会显示成乱码。
- 保存即生效：会重建通知渠道，站内通知立刻同时投递到用户邮箱，**不需要重启**。
- **测试**：真的发一封信（默认发给「发件地址」或 SMTP 账号，可临时改收件地址），
  投递失败时把 SMTP 的异常原样报出来（例如 `SMTPAuthenticationError` 通常是授权码没用对）。

## Telegram 通知

填 **Bot Token** 即启用；用户在个人中心绑定 Telegram 后即可收到站内通知。

- **测试**：调 `getMe` 验证 Token，并把 Bot 名字/用户名回显出来，便于确认没有填错 Bot。

## AI 模型设置

任何 **OpenAI 兼容**端点都能用：官方 API、中转站、本地 Ollama / vLLM / one-api…改 `base_url` 即可。

- **多密钥**：一行一个（逗号、分号也认），每次调用轮换；单把 key 被限流时不会整体不可用。
- **用户侧消费点**：用户端「AI 助手」页（`/assistant`）→ `POST /api/user/ai/ask`。
  管理员没配置时，用户端**不会显示可点的入口**，页面直接说明原因。
- **配额**：`每用户每日提问上限`（默认 20，0 = 不限）。计数在进程内按天累计（与限流器同一取舍：
  单进程部署准确；多进程下最坏相当于配额放大到「上限 × 进程数」）。
- **上下文**：客户端传来的历史只接受 `user` / `assistant` 两种角色并截断到最近 8 轮——
  否则用户可以塞一条 `role=system` 把自己变成系统提示词，绕开你设定的人设。
- **测试**：真实发一次极小的 completion，把模型与回复回显出来。

## IP 与地理位置

给「登录与安全日志」补上 IP 归属地，风控审查时不用再去查 IP 库。两种提供方任选：

| 提供方 | 需要准备 | 说明 |
| --- | --- | --- |
| 腾讯地图 IP 定位 | 一个 WebService Key | 无需自备数据库 |
| 本地 MMDB | GeoLite2 / IPIP 的 `.mmdb` 路径 + `maxminddb` 依赖 | 不联网、可离线 |

- **性能**：查询结果按 `缓存时长` 缓存（默认 24 小时），**失败结果只缓存 5 分钟**（瞬时故障不至于让
  一个 IP 一整天查不到）；未配置提供方时**一个外部请求都不发**，写日志不会变慢。
- 保存配置会清掉提供方与 IP 两级缓存，所以「改了立刻生效」。
- 归属地缺失不编造：查不到就是空，日志列表里不显示这一行。
- **测试**：查一个指定 IP（默认 `8.8.8.8`）并把地区/运营商回显出来。

## 实现位置

| 文件 | 作用 |
| --- | --- |
| `backend/integrations/__init__.py` | 能力注册、字段表读取、掩码、保存与测试的调度 |
| `backend/integrations/<slug>.py` | 每个能力一个模块：`SPEC`（字段表）+ `apply()` + `test()` |
| `backend/api/capabilities_admin.py` | 后台 API：`/api/admin/capabilities*` |
| `backend/api/assistant.py` | 用户端 AI 助手：`/api/user/ai/*` |
| `admin_frontend/src/views/Settings.vue` | 能力卡片与按字段表渲染的配置抽屉 |
| `user_frontend/src/components/ui/CaptchaChallenge.vue` | 登录/注册页的人机验证挂件 |
| `scripts/smoke_test_capabilities.py` | 90 项断言：阀门、密钥不外泄、保存即生效、测试是真在测 |

### 加一个新能力要写什么

1. 新增 `backend/integrations/<slug>.py`：声明 `SPEC`（标题、说明、分组、字段表，字段带 `type` /
   `secret` / `options` / `required` 等），需要落地副作用就写 `apply(db)`，能测就写 `test(db, payload)`，
   需要自定义「是否配齐 / 是否启用」就写 `is_configured(values)` / `is_enabled(values)`。
2. 把 slug 加进 `CAPABILITY_MODULES`。
3. 后台**不用改前端**：能力总览与配置表单都是按字段表渲染的。

字段类型支持 `str` / `secret` / `int` / `bool` / `select`；`select` 传非法值时回落默认值，
`int` 传非法值同样回落——保存动作不会因为一个笔误的值把配置写坏。
